## 2. Product purpose and binding user decisions

The PTMagic analyzer's metric-development objective is **accurate descriptive identification and characterization of market regimes for any user**, not profitability prediction, personal LONG/SHORT entry/exit optimization or a quota of metrics. All MarketTrend durations are user-configurable; diagnostic StoreDataMaxHours=96 is NOT a universal design ceiling. Preserve source-validity, pinned closed-candle timestamps, population/coverage rules and the 300-second analysis freshness safeguard. Do not invent fixed universal regime thresholds.

**Delta design:** the user rejected MetricDelta as a new registered metric and rejected adding ComparisonMinutes. Instead the existing **MarketTrendRelation = Delta** applies to an existing Metric referenced by an existing MarketTrendName. **Delta = current metric value − metric value one MarketTrend.TrendMinutes earlier.** GlobalSetting, SMS activation and SMS OffTriggers use the same principle, with the existing MinChange/MaxChange bounds and feature units. Compare real source observations; for completed-period measurements, avoid counting identical reported periods across multiple raids as independent changes. Missing, stale, invalid, incompatible and repeated-source-time histories produce UNAVAILABLE, not zero. Preserve old Absolute, Relative and RelativeTrigger semantics.

**Mandatory test-analyzer rule:** whenever runtime tests will be needed for a newly authorized code change, update the **single existing test fixture** at Tests/Settings/settings.analyzer.json in that same development work. Add relevant diagnostic GlobalSettings/SMS/OffTriggers, prioritize the new GS first so it can ACTUALLY activate, increment fixture version, update README and retain old diagnostic coverage unless expressly changed. No new test analyzer, branch, directory reshuffle or second fixture. The app also contains existing default/development analyzer configuration files **outside Tests/Settings**; these are NOT duplicate runtime-test fixtures and MUST NOT be deleted or edited as part of this rule.

**Descriptive Name rule:** optional field lives at the TOP of MarketAnalyzer settings; for the user's test fixture its value is exactly the **analyzer version number string** (currently **2.6.3**), without a PTM or application-version prefix, leading v or English name. The raid header must retain literal **RAID SUMMARY**. An empty/omitted value displays **RAID SUMMARY #N**, not **Raid #N**. Maintaining this unchanged marker preserves existing Monitor Logs streaming and previous-summary parsing.

**Crucial compatibility instruction from user:** before changing code, **identify and explain compatibility impacts to the user first**. The initial suggestion to remove SUMMARY would have required changing multiple log readers; the user instead chose to keep RAID SUMMARY. Do not initiate complex changes/reverts when a small change to the requested behavior is simpler. Explain exact proposed repository changes and get explicit approval BEFORE every future GitHub write. No new branches, personal settings, strategy changes, or unrelated PTMagic work.
