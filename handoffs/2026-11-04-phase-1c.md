## Established scope and architecture

PTMagic 2.10 is the market-analysis expansion across roadmap Phases 0–6. Phase 0 architecture audit was completed. The implementation must preserve the existing legacy analyzer and ProfitTrailer behavior and avoid introducing an independent analytics framework.

### Completed or reported implemented at the handoff

**Phase 1A — normalized market-data foundation:**
- Normalized Binance Futures 5-minute OHLCV ingestion and a centralized `MarketDataStore` / `MarketDataService`.
- Incremental data updates, bounded cache using `StoreDataMaxHours`, timestamps, validity/staleness tracking.
- Frozen exact Phase 0-resolved eligible market universe; trend-specific `MaxMarkets` / `TrendThreshold`, underlying-type filtering.
- Monitor-facing snapshots.
- Treat completion as implementation state, not proof that first-raid cross-sectional readiness is correct.

**Phase 1B — normalized market-analysis metrics:**
- `PriceTrend`, `MedianPriceTrend`, `MeanMedianSpread`, `Breadth`, `Dispersion`, `RelativeStrengthMarket`, `RelativeStrengthBTC`, and `Concentration`.
- Existing `Concentration` is specifically **Top10 Return Advantage**, not volume concentration.
- Partial Phase 4 trigger wiring for explicit `Metric` evaluation through GlobalSetting / SMS / OffTrigger, including global metric SMS support.
- An omitted `Metric` retains legacy evaluation. Missing, invalid or stale normalized metrics must fail closed for normalized triggers.

## Blocking observation: first-raid metric readiness

Reported runtime observations:
1. First raid: **756/756 normalized series fetched successfully**, **654,696 candles**, **717 eligible symbols**, yet only **259/1,434** four-hour per-asset metrics were valid.
2. Second raid: **557 series refreshed** and **1,434/1,434** four-hour per-asset metrics became valid.
3. Third raid: **no klines** requested.

The **root cause is not established**. One hypothesis is that the initial refresh crossed a 5-minute candle boundary, producing mismatched closed-candle endpoints across symbol series. This must be tested against real source code, timestamps and logs before claiming causation.

### Required investigation before expanding Phase 1C

1. Review actual market-data refresh and metric-aggregation code at current application-branch HEAD.
2. Trace selection of each symbol's last completed 5-minute candle, common analytical endpoints, and construction of 4-hour windows.
3. Establish why the first-raid denominator was 1,434 and why 259 metrics qualified when all 756 series were reported fetched.
4. Verify whether refreshes spanning candle boundaries can yield inconsistent per-symbol history endpoints; distinguish any other causes found.
5. Implement the **smallest correctness change**, without defeating incremental refresh, increasing unnecessary Binance calls, or changing legacy semantics.
6. Enforce cross-sectional coverage/readiness and fail-closed behavior for normalized metrics and explicit normalized triggers.
7. Verify first, subsequent, and no-new-candle raids with timestamps, coverage and test evidence; update issue 001 and STATUS accordingly.

## Phase 1C implementation sequence

1. **Per-asset ATRP:** compute True Range and ATR with explicitly defined lookback, smoothing/seed behavior and denominator using normalized 5-minute OHLCV. Specify validity and staleness rules.
2. **Market median ATRP:** compute from the exact Phase 0 eligible universe; define relation to trend windows / `TrendMinutes` and its valid-sample denominator.
3. **Volatility breadth:** share of valid assets above a configurable ATRP threshold; explicitly account for coverage.
4. **Quote-volume expansion:** compare recent quote-volume against a prior comparable window; define zero-baseline and insufficient-history behavior.
5. **Volume-expansion breadth:** proportion of valid universe meeting expansion criteria, with explicit denominator.
6. **Volume concentration:** concentration of traded quote volume; this is **distinct from the existing return-based `Concentration`**.

## Implementation constraints

- Reuse existing `MarketDataStore`, `MarketDataService`, metric registry/resolver, Monitor snapshots and trigger infrastructure.
- Derive metrics from shared normalized OHLCV data; do not create parallel historical-data processing or unnecessary additional Binance calls.
- Maintain identical legacy behavior unless an explicit metric is selected, while invalid/stale normalized inputs fail closed.
- Preserve Phase 0 universe eligibility, filtering and per-trend boundaries.
- Avoid premature additions of derivatives, liquidity or other later-phase features.
